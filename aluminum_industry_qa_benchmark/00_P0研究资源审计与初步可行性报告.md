# P0：研究资源审计与初步可行性报告

日期：2026-10-21（Asia/Shanghai）  
范围：只做 Water-MAS 解读、本地资料与运行数据只读审计、三类 Benchmark 的初步可行性判断；不生成问答、不训练模型、不实现 Agent。

## 结论先行

**总判断：CONDITIONAL GO（有条件推进）。** 本地资源足以启动一个小规模、证据可追溯的可行性验证，但尚不足以直接宣布已有可公开、可评价的电解铝 Benchmark。

最稳妥的下一学习单元是：先为日报中的 12 个字段建立“字段语义—单位—生成时点—可用任务”证据表，并让工艺专家确认其中至少一组可用字段。完成后才设计少量、由独立程序计算答案的统计型题目。

| 方向 | P0 判断 | 原因 |
|---|---|---|
| A. 专业知识问答 | CONDITIONAL GO | 三套教材的章节覆盖宽，但完整书籍是扫描件，尚无逐页可定位、经审核的证据池。 |
| B. 真实运行数据问答 | CONDITIONAL GO | 21 台槽、30,691 条日报记录可支撑检索/统计/比较；字段语义、缺失、重复和事件状态尚需确认。 |
| C. 知识与数据融合问答 | CONDITIONAL GO（后置） | 可以做“描述性分析 + 适用条件说明”，但不能在字段和教材证据未核验前作因果解释或工程处置建议。 |

以下“论文事实”来自 Water-MAS 正文；“本地资料事实”只陈述文件或数据中可直接验证的内容；其余结论分别标为“推断”或“本地改造方案”。

## 1. Water-MAS：可迁移什么，不能照搬什么

### 1.1 论文事实：问题、系统与数据集

Lin et al. 的 Water-MAS 试图让 LLM 在水环境知识问答与多步数据工具调用中协作。论文 PDF 第 2 页 §2.1.1 说明了三类 Agent：

- **Planning Agent**：将用户任务分解为可执行步骤并把计划交给后续循环；
- **Execution Agent**：根据输入的 mask message list 选择工具及参数、执行调用；
- **Checking Agent**：核查当前步骤结果是否满足预期，不一致时向执行 Agent 反馈重试指令与下一步提示，并判断任务是否结束。

论文事实（第 2—3 页 §2.1.2、图 1c）：Instruction-Data Decoupling 不把原始工具输出、提示和调用历史拼接在同一上下文中，而是维护三层信息：保存完整工具输出的 **complete message list**、以匿名 ID 代替大载荷的 **masked message list**，以及由摘要模块产生的 **summary message list**。前后转换层在匿名 ID 和完整 payload 间映射，因此 Agent 主要面对压缩表示，而工具仍处理原始数据。

论文事实（第 3 页图 1d；第 4 页 §2.2）：

| 数据集 | 规模与构成 | 作者明确披露 |
|---|---:|---|
| 知识型 | 260 道四选一题 | 以 52 份水环境法律、法规与标准为基础；Law 20、Management 55、Monitoring 120、Emission 30、Risk control 10、Quality 25；题目均经人工验证。 |
| 任务型 | 114 道工具调用题 | M1=48、M2=24、M3=27、M4=15；M1—M4 是完成任务**至少需要** 1—4 个工具的分级；每题经人工分类，并配有人审的参考工具调用序列。 |

论文事实（第 4 页 §2.2，图 1b）：系统有 14 个工具，文中示例涉及采样点生成、高程/水深数据查询、知识库检索、相关分析、缺失值插补和 LSTM 预测。任务型数据使用的水文/监测资料、GEBCO 数据以及适用范围在正文中有概述；文本还说明三个海湾的水深数据**未纳入数据集**。

论文事实（第 4—5 页 §2.3—2.4）：知识题比较了纯 LLM、单执行 Agent、Plan+Execute、Execute+Check 与三 Agent；任务题以工具调用 Precision、Recall、F1 等评估。M4 任务中，三 Agent 的 F1=0.68，单 Execution Agent 的 F1=0.43（第 7 页 §3.1 / 图 3）；耦合与解耦比较表明复杂任务中解耦更有利，而简单 M1 并非必然受益（第 8 页 §3.2 / 图 4）。

### 1.2 未披露或当前未找到的材料

**论文未充分披露**：260 道题的逐题来源定位、题干生成提示、标注者数量/一致性、114 题的完整工具 schema、参考调用序列、参数容差、数据快照版本与拆分策略。正文将更多细节指向 Text S4、S5、S7 及 Tables S1—S4，但本地只有正文 PDF，未发现这些补充材料。

**公开检索结果**：期刊页核实了标题、DOI、260+114 规模与摘要性结论；以 DOI、题名和 GitHub 为关键词的检索没有找到可核验的官方代码仓库、题库下载、工具配置或补充材料下载页。此处是“**未找到**”，不是“确定不存在”。复现时不可把作者的结果或工具调用序列视为可直接获得的资产。

### 1.3 跨领域迁移判断

| Water-MAS 设计 | 原论文所解决问题 | 电解铝潜在对应 | 迁移障碍 | P0 建议 |
|---|---|---|---|---|
| 52 份规范→知识选择题 | 法规检索与术语判断 | 教材/规范/已授权工程资料→可定位知识题 | 扫描教材、版权、不同槽型/年代的适用条件 | 可采用“证据定位 + 条件”框架，不能只改名换领域。 |
| 监测数据→工具题 | 数据获取、比较、统计、预测 | 日报字段→时间窗查询、统计、跨槽比较 | 字段语义、单位与生成时点未全明 | 先限定为原始或可确认的日报字段。 |
| M1—M4 | 最少工具数分级 | 单字段统计至跨表多步审计 | 工具数不等于推理难度、数据质量难度或工艺难度 | 保留为一个标签，另加证据完整性和语义风险等级。 |
| Plan/Execute/Check | 降低复杂调用错误 | 查询计划、程序执行、规则核验 | 当前没有可验证工具接口及金标准调用链 | 仅作为后续 E4 候选基线，不预设优于单 Agent。 |
| 指令—数据解耦 | 长序列/大载荷工具输出 | 日报长窗口或多槽结果的 ID 化与摘要 | 数据量是否真正触及上下文压力尚未测量 | 只有在同一任务的耦合/解耦可公平比较时再评估。 |

**推断**：Water-MAS 的真正可迁移贡献是“人审的可执行金标准 + 工具结果核验”，不是“三 Agent”标签。电解铝项目若没有可重放的查询程序与字段证据，即使复制架构也不构成 Benchmark。

## 2. 本地专业知识资料审计

### 2.1 本地资料事实

发现三套主体资料：

| 资料族 | 可见 PDF 数 | 覆盖线索 | 可用于什么 | 主要限制 |
|---|---:|---|---|---|
| 《现代铝电解》 | 40（含完整书） | 基础原理、结构、焙烧启动、操作、参数测量、槽电阻/极距、氧化铝与分子比控制、槽况分析、维护等 | 候选知识来源 | 完整书 650 页；机器文本提取仅 1 页非空。 |
| 《铝电解生产技术》 | 13（含完整书） | 基础、原料、结构、焙烧启动、常规操作、控制、病槽、能耗等 | 候选知识来源 | 完整书 260 页；机器文本提取仅 1 页非空。 |
| 《铝电解技术问答》 | 20（含完整书） | 基本原理、焙烧启动、非正常期/正常生产管理、病槽、测量、控制、能耗等 | 可寻找候选问答主题 | 完整书 284 页；机器文本提取仅 1 页非空。 |

另有 51 个工程经验 Markdown 文件和一套“启动期工程经验知识库”。它们可作为待核验的本地工作材料，不自动等同于教材事实、企业规程或普适工艺事实。

### 2.2 P0 知识覆盖判断

从章节名称这一**资料目录事实**看，资料覆盖了：基础化学与术语、设备结构、焙烧/启动、正常运行、下料/浓度/温度/分子比/槽电阻控制、测量与计算机控制、阳极效应/病槽/内衬破损、能耗与槽况分析。

**推断**：可优先形成以下可信问答候选，而不是直接出题：

1. 术语、单位、参数定义；
2. 有明确适用条件的基础机理；
3. 教材中存在明确表述且可页码定位的操作/测量原则；
4. 明确区分槽型、工艺阶段和时间条件的异常现象说明；
5. 证据不足时拒答。

不应先做：无条件的“最佳参数”题、单一数值阈值题、跨槽型泛化的工程处置题，以及将工程经验 Markdown 直接作为唯一标准答案的开放题。

**本地改造方案**：继续前先选取约 20 个候选页，进行 OCR、人工抽查、页码与书名定位，并为每条证据标注“适用槽型/阶段/来源版本/审核状态”。这比先批量生成题目更重要。

## 3. 真实运行数据审计

### 3.1 文件与来源边界

本地《数据说明文件》自述数据集含“焙烧控制过程记录、出铝量预测模型、工艺参数感知数据、电解槽日报”，并自述日报有 26 个 Excel 文件。实际物理目录中发现：**21** 个旧式 `.xls` 日报与 3 个 `.xlsx` 文件。因此“26”与实际“21”不一致，P0 不假设缺少文件可忽略。

说明文件虽然写有“完全共享”，但这只是**本地资料事实**；公开发布派生题目、数据切片或代码的权限仍需项目方核验。

### 3.2 日报（可直接审计的主要候选数据）

| 项目 | P0 只读实测结果 |
|---|---|
| 文件/设备 | 21 份日报，对应 21 个槽号：2726—2736、2827—2836。 |
| 记录量 | 30,691 条数据行（不含表头）。 |
| 时间 | 各槽起始日不同；汇总范围 2017-04-26 至 2021-06-02。绝大部分表为中文字段，2736 为英文等价字段。 |
| 时间连续性 | 按每槽不同日期去重后，文件内部起止日期之间合计 126 个日历日没有记录；不能把日报机械当作无间断日序列。 |
| 完全重复 | 21 份表各有 3 条完全重复数据行，合计 63 条。去重口径必须在任务 gold program 中固定。 |
| 12 列字段 | 槽号、时间、氟化铝料量、效应时间、平均电压、设置电压、效应电压、工作电压、设定NB、出铝指示量、噪声、效应状态（2736 为英文表头）。 |
| 缺失 | 中文 20 份日报中，效应时间/效应电压各缺 26,223/29,252（89.6%）；设定NB 缺 8,033（27.5%）；氟化铝料量缺 7,390（25.3%）。工作/设置电压各缺 162（0.6%）。 |

**本地资料事实**：日报确含“效应状态”等字段；但目前没有找到状态代码本、采集口径、单位说明或生成时点。因此“效应状态=某一特定事件标签”是**待核验**，不能据此构造真实异常事件金标准。

## 4. 哪类数据问题能做

| 任务类别 | P0 可行性 | 条件与禁止事项 |
|---|---|---|
| A. 数据检索 | 可直接实施（日报） | 仅查询字段名已固定、时间/槽号明确的原始日报；先声明重复行处理。 |
| B. 统计计算 | 可直接实施（日报） | 均值、最大值、计数等由独立程序计算；必须返回缺失/去重规则。 |
| C. 趋势比较 | 需补充条件 | 限制为同槽同字段的历史窗口；先处理缺失日，避免将日期空档误读为趋势。 |
| D. 多设备比较 | 需补充条件 | 用相同字段、同一时间窗、同一统计口径；字段是否跨槽可比仍需工艺确认。 |
| E. 异常事件分析 | 当前不可实施 | 缺少“效应状态”等编码、生成时点与人工事件记录的定义，不能把名称相似的列当作可靠事件标签。 |
| F. 知识+数据融合 | 需补充条件 | 答案只能陈述可见数据现象和经定位的知识适用边界；不得由相关性推出故障原因或因果结论。 |

## 5. P0 的研究决策与下一步选项

### GO / NO-GO 表

| 检查项 | 结论 | 证据或缺口 |
|---|---|---|
| 专业资料是否足够 | 有条件足够 | 覆盖广；扫描件 OCR 与页码证据不足。 |
| 数据字段是否清楚 | 否，待核验 | 字段名可读，语义/单位/状态码/生成时点不完整。 |
| 标准答案可否验证 | 部分可以 | 日报检索与统计可由程序复算；事件与预测类不行。 |
| 泄漏是否可控 | 部分可以 | 需排除预测列及任何事后派生字段；固定 as-of 规则。 |
| 是否有公平基线 | 尚未建立 | 先用确定性程序工具，后比较 LLM/RAG/Agent。 |
| 创新性是否已成立 | 否 | 当前只是可行性线索；高质量贡献取决于 gold evidence、工具可重放和独立审核。 |

### 最值得优先验证的问题

**RQ-P0.1：能否把经字段确认的日电解槽日报，稳定转换成带数据契约、可独立重放、无泄漏的统计型工具调用任务？**

这是比直接验证 Multi-Agent 更低风险、也更能决定项目是否成立的问题。若 10—20 道此类题都不能做到字段可解释、程序可复算、专家可接受，则不应扩展为复杂融合 Benchmark。

### 等待确认的下一学习单元

建议的 P1 只做“日报字段与知识证据校准”：

1. 读取已有数据契约、字段说明和历史审计结果；
2. 建立 12 个日报字段的证据表，明确单位、原始/派生属性、生成时点、缺失和可用任务；
3. 从教材中 OCR 并人工校验少量与这些字段直接相关的页；
4. 输出不超过 10 个候选题的**设计卡**，但不生成正式数据集。

在用户确认前停止，不进入 P1。
